## 步骤

### 1. 准备
- 查看并处理当前未提交修改 `dmg的替身`（stash 或单独提交）
- `git fetch upstream`
- 从 `local/brand-tiancheng` 建工作分支 `local/upstream-fixes-202609`，原分支不动

### 2. 逐个验证（每个 pick 前先 `git show <sha>` 审查 diff）
带 * 的候选先 grep 确认所依赖的功能在本地存在，不存在则跳过并记录：
- #1242*（Guide now 队列机制，改动含 agent.rs 253 行，重点核对与本地 queue cut-in 改动 660b3547 的相容性）
- #1285*（研究归档草稿功能）、#1293*（auto-review）、#1313*（figure QA）、#1321*（路径点击）、#1332*（命令面板）、#1337*（会话分组）

- 批 1（v1.12 尾）：#1235 图像像素限制、#1237 新窗口空白会话/审批丢失

### 4. 全量验证
- `cargo fmt --all -- --check`（漂移则格式化单独提交）
- `cargo test --workspace`
- `cd ui && cargo check --target wasm32-unknown-unknown`
- `cd ui-tests && npm ci && npx playwright test`

### 5. 记录与收尾
- `report/` 写摘取报告：成功清单、跳过项及原因、验证结果
- 每个 pick 保留独立提交便于追溯；完成后等你确认再合并回 `local/brand-tiancheng`（是否推送 gitlab 由你决定）

## 风险与回退
- 主要冲突源是 crate 重命名（机械可解）与本地 UI 定制重灾区（手工融合，量小）
- 预期个别候选因依赖缺失或冲突过深被剔除，属正常，记录即可
- 工作分支独立，任何问题可整批放弃，原分支零影响
- 数据库零改动，无兼容性风险，无需备份迁移
