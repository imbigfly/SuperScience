# 隔离探索分支

探索用于试验新的科研方向，同时不改变项目主线。它不同于普通对话分支：每个探索都有持久、独立的工作区，文件、Artifact、运行、决策和外部资源记录也保持私有。

## 创建和使用探索

1. 在 Wisp 原生会话中完成一轮对话。
2. 在任一具有不可变项目状态 revision 的已完成 assistant 回复上选择**开始探索**，命名并创建。
3. 正常使用探索。顶部 banner 会显示隔离等级，并提供**查看差异**、**设为主线**、**归档**和**丢弃**。
4. 从侧栏 source 会话下的探索分组切换主线和多个兄弟探索。

Wisp 会在每个成功的 native 主线轮次结束后记录不可变的 `ProjectStateRevision`，冻结工作区快照、对话归档、Artifact heads、Runs、Decisions、外部资源摘要以及稳定的可视轮次索引。工作区 blob 按内容寻址复用，revision 元数据则周期性保存完整 manifest，其余轮次保存 delta。轮次结束前由外部编辑器写入的文件也会进入快照。

功能升级前的历史无法可靠重建，其**开始探索**入口会保留但禁用；最新完成轮次仍可使用当前状态兜底。上下文压缩不会改变 revision 的轮次索引或已归档对话。ACP v1 没有服务端 fork，因此 ACP 会话暂不支持探索。

## 设为主线

**设为主线**是 fast-forward，不是通用 merge。只有主线仍与探索检查点完全一致、探索没有活动 Run，也没有发生不支持的引用变化时才能执行。

确认前应检查五类差异：

- 文件
- Artifact
- 运行
- 决策
- 外部副作用

如果主线已经前进，Wisp 会保留探索供查看，但拒绝晋升；不会自动拼接对话或解决文件冲突。

## 隔离与外部副作用

普通项目文件会复制到探索工作区，不使用可写 hard link。符号链接、device、socket、Git 元数据和大型引用文件可能显示为“部分隔离”；引用内容发生变化会阻止 fast-forward。

远程作业、邮件、数据库写入、MCP/App 写操作和其他网络副作用无法通过丢弃探索来撤销。Wisp 会记录并在执行前警告，但不会声称能够回滚这些操作。

归档会只读保留探索。丢弃只删除探索私有记录和经过严格校验的 app-data 工作区，不会删除项目主线或兄弟探索。
