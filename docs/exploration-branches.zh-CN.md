# 隔离探索分支

探索用于试验新的科研方向，同时不改变项目主线。它不同于普通对话分支：每个探索都有持久、独立的工作区，文件、Artifact、运行、决策和外部资源记录也保持私有。

## 创建和使用探索

1. 在 Wisp 原生会话中完成一轮对话。
2. 在最新的已完成 assistant 回复上选择**开始探索**，命名并创建。
3. 正常使用探索。顶部 banner 会显示隔离等级，并提供**查看差异**、**设为主线**、**归档**和**丢弃**。
4. 从侧栏 source 会话下的探索分组切换主线和多个兄弟探索。

第一个候选会开启一轮探索。此后从同一主线头创建的候选复用同一个不可变检查点，但各自拥有独立工作区。只要当前轮仍有活动候选，Wisp 就会冻结探索源对话和该项目的全部主线工作区写入，其他会话也不能另开一轮竞争探索；用户仍可新建其他对话，用于讨论和只读检查项目。晋升一个候选即可结束本轮；也可以归档或丢弃全部候选，放弃本轮并恢复正常项目写入。晋升时，同轮其他候选会自动归档。

Wisp 会在每个成功的 native 主线轮次结束后记录不可变的 `ProjectStateRevision`，冻结工作区快照、对话归档、Artifact heads、Runs、Decisions、外部资源摘要以及稳定的可视轮次索引。工作区 blob 按内容寻址复用，revision 元数据则周期性保存完整 manifest，其余轮次保存 delta。轮次结束前由外部编辑器写入的文件也会进入快照。

快照扫描会按 Git ignore 语法读取各级 `.gitignore` 和项目内的 `.wispignore`，包括 `!` 反向规则。对于需要留在项目中、但不应进入探索历史的文件，可将规则写入 `.wispignore`。Wisp 还会在任意层级自动跳过 `.git`、`.pixi`、`.venv`、`node_modules`、`target`、Python 缓存以及内部 `.wisp` artifact/output 等明确的生成目录；`.github` 这类源码配置目录不会被一概排除。

检查点采用增量更新：路径、大小和修改时间均未变化的文件直接复用已有的内容寻址 blob，只有变化文件才会重新读取和哈希。强快照的上限为单文件 32 MiB、每个检查点合计 64 MiB 和 4,096 个文件；超出范围的内容会保存为明确的弱引用，而不是复制数据。扫描和 blob 写入均可取消，因此即使正在记录 revision 元数据，**停止**也能结束当前轮次。

较早的已完成轮次仍显示**开始探索**入口，但保持禁用：探索轮次有意只从当前头开始，以保证每个候选都具备晋升基础。上下文压缩不会改变已归档对话。ACP v1 没有服务端 fork，因此 ACP 会话暂不支持探索。

## 普通对话分支

普通对话分支在侧栏使用分支图标，也会直接显示在创建它的消息检查点下方。分支建立后，main 可以继续向前推进；每个分支则拥有独立的后续上下文。

当分支完成聚焦任务后，右键选择**回并**。Wisp 只读取该分支从检查点之后新增的消息，并生成一份自包含的总结草稿。用户检查和编辑草稿后，确认文本会作为普通、可读的对话上下文追加到 main 当前末尾。main 在检查点之后新增的轮次不会参与比较，不会被截断、替换，也不会进入分支总结。回并后分支仍然保留，可以继续审查或推进。

main 中的回并总结以紧凑的**回并结果**卡片呈现，不会在时间线中直接铺开长文本。点击卡片可在窗口中查看完整 Markdown，关闭后回到原对话。该卡片只是展示层：底层仍是 main 中可被后续模型直接读取的普通 assistant 上下文，并通过独立 provenance 记录来源分支。

总结草稿支持**重新生成**和**引导生成**。重新生成只依据检查点后的分支变更重新起草；引导生成会打开独立窗口接收用户引导词，并按【变更】【当前版本】【用户引导】三段上下文生成新版本。新版本只替换待确认草稿，不会自动写入 main。

单个分支仍可使用**删除分支**。原来的**比较分支**、**转为独立会话**以及会改写共同祖先并清理整个分支家族的收敛动作，已不再属于普通对话分支流程。

这些操作只处理对话历史，不会合并、恢复或回滚项目文件、Run、Artifact 与外部副作用。如果需要一起比较并晋升项目级变化，请使用隔离探索。

## 设为主线

**设为主线**是 fast-forward，不是通用 merge。只有主线仍与探索检查点完全一致、探索没有活动 Run，也没有发生不支持的引用变化时才能执行。

确认前应检查五类差异：

- 文件
- Artifact
- 运行
- 决策
- 外部副作用

探索期间，Wisp 会阻止自身发起的主线写入。外部编辑器和进程不受这个锁控制，因此晋升前仍会重新扫描项目；只要主线不再匹配检查点，就会拒绝晋升。Wisp 不会自动拼接对话或解决文件冲突。

## 隔离与外部副作用

普通项目文件会复制到探索工作区，不使用可写 hard link；被 ignore 的路径不会进入快照。符号链接、device、socket、Git 元数据以及因大小或总预算而保留的引用文件可能显示为“部分隔离”；引用内容发生变化会阻止 fast-forward。

远程作业、邮件、数据库写入、MCP/App 写操作和其他网络副作用无法通过丢弃探索来撤销。Wisp 会记录并在执行前警告，但不会声称能够回滚这些操作。

归档会只读保留探索。归档或丢弃全部候选会放弃本轮并解除主线冻结；主线前进后，过期的已归档候选不能再次恢复。丢弃只删除探索私有记录和经过严格校验的 app-data 工作区，不会删除项目主线或兄弟探索。
